#### A2. 标的品类识别（解决限值适用性）★价值最高

**为什么**：现在「水分 14.5%」会**同时**对「籼米」报一致、对「籼稻谷」报偏离——因为系统不知道合同标的是稻谷还是大米。同一个指标出现互相矛盾的结论，影响专业观感。

**怎么做**：

1. `backend/app/modules/contract_parser/schema.py` → `ContractFacts` 增加字段：
   ```python
   subject_category: str = ""   # 如 "籼稻谷" / "粳稻谷" / "大米" / "优质籼稻谷"
   ```
2. `backend/app/modules/contract_parser/facts.py` → 新增 `extract_subject_category(text) -> str`：
   - 从合同全文找品类词：`稻谷` / `大米` / `籼` / `粳` / `晚籼` / `优质` 的组合
   - 优先在「标的」「品种」「质量标准」相关句子中匹配
   - **抽不到就留空，不猜**
3. `backend/app/modules/standard_check/compliance.py` → `check_compliance()` 增加适用性过滤：
   - 若 `facts.subject_category` 非空：只保留 `applies_to` 与其匹配（包含关系，如 `"籼稻谷"` 匹配 `applies_to="籼稻谷"`）的限值
   - 若为空：**保持现状**（全部列出 + 回传 `applies_to`），保证向后兼容
   - 新增返回字段 `filtered_out_count`，说明过滤掉了几条（保持透明，不静默丢弃）

**验收**：
- 新增单元测试：构造含「籼稻谷」的合同，水分 14.5% 应只对籼稻谷（≤13.5%）报偏离，**不再出现「籼米一致」**
- 抽不到品类的合同，比对结果与改动前完全一致
- 三条验证命令全过

## 4. 红线与已知坑

### 4.1 绝对不要做

| 项 | 原因 |
|---|---|
| `.env` 入库 | 含 API Key |
| 删除 `data/` 或 `.codebuddy/` | 含知识库与用户合同 |
| 引入 Docker 依赖 | 主力机仅 128GB，torch 镜像 + 构建缓存约 20~30GB |
| Windows 装 torch / sentence-transformers | 2.5GB+ 且 6GB 显存收益有限，用 `hashing` 兜底 |
| 引入 UI 框架（Element Plus 等） | 前端保持零运行时依赖 |
| 引入 LangGraph / LangChain | 技术栈堆砌，AgentArts 自带工作流 |
| 引入 PostgreSQL / Milvus / Redis / K8s | 当前数据量用不上，属基础设施炫技 |
| 编造标准数值 | 查不到就留空 + 标注来源 |

### 4.2 Provider 层必须保留

**不要因为"看起来过度设计"而拆掉它。** 它已被验证过价值：本次会话中向量化从 `hashing` 换到 `cloud`，**业务代码零改动，只改了一条 `.env`**；rerank 从无到有也是新增一个实现类。`mock` / `disabled` 是演示可靠性保障。

可以改的是**措辞**（"外部能力通过 Provider/Tool 接口隔离，不同环境允许不同实现"），**不是架构**。

### 4.3 环境坑

| 现象 | 说明 |
|---|---|
| 本地请求偶发 **502 空响应** | 本机装了系统代理（`127.0.0.1:7897`），httpx 自动读取它，连 `127.0.0.1` 的请求也被 `CONNECT` 隧道转发，长耗时接口撞代理超时。`.env` 的 `HTTP_PROXY=` **无法覆盖**（pydantic 不写回 `os.environ`）。测试脚本已用 `trust_env=False` 规避 |
| 断网后检索报未就绪 | `EMBEDDING_PROVIDER=cloud` 依赖外网。断网前切 `hashing` + `RERANK_PROVIDER=disabled` |
| 合同正文发往第三方 | `cloud` 会把依据库语料与合同条款发到 SiliconFlow。敏感合同切 `local` |
| `git status` 中文名显示八进制转义 | `core.quotepath` 默认行为，不影响仓库内容 |
| CRLF → LF warning | `.gitattributes` 统一行尾的预期行为，不是错误 |

### 4.4 架构铁律（改代码前必读）

1. 外部依赖一律走 Provider 层；业务模块**不得** import 厂商 SDK
2. 业务代码**禁止**直接读 `os.environ`，一律通过 `settings`
3. 相对路径必须经 `settings.path_of()` 解析
4. **抽取值必须带 evidence** —— 这不是可选项，"可信性"就是立身之本
5. 未就绪要显式报错（`ProviderNotReadyError`），不静默返回空结果
   → 已扩展为「**解析门禁**」：见 `contract_parser/gate.py`，必备字段缺失时必须留下 `gate` + `[门禁/*]` 告警
6. 模块之间不直接互相 import
7. **数值不交给 LLM** —— 合规比对要求精确
8. **判不了就说判不了** —— `review` 状态优于错误的确定结论
